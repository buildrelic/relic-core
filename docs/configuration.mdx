All runtime configuration is environment variables, loaded from `.env` into a
pydantic-settings model ([`config.py`](https://github.com/buildrelic/relic-core/blob/main/packages/relic-core/src/relic/config.py)). Secrets are
optional, so importing config (and `relic --help`) never needs a populated `.env`.
`get_settings()` reads and caches them.

## Setup

`just setup` does the full setup. For just the configuration pieces:

<Steps>
  <Step title="Create your .env">
    ```bash
    just env
    ```
    Copies `.env.example` to `.env` if missing. Fill in your keys.
  </Step>
  <Step title="Start the store">
    ```bash
    just up
    ```
    Starts Postgres on `localhost:5432`. The engram schema is applied
    automatically on first use.
  </Step>
  <Step title="Confirm what is configured">
    ```bash
    just doctor
    ```
  </Step>
</Steps>

## Variables

| Variable | Default | Required for | What it does |
|---|---|---|---|
| `DATABASE_URL` | `postgresql://relic:relic@localhost:5432/relic` | `ingest`, `load`, `recall`, `query`, `eval`, the daemon | the engram store. The default matches `docker-compose.yml`; point it at a hosted Postgres later |
| `RELIC_WORKSPACE` | `local` | none | the workspace every locally-ingested memory lands in. The web app writes with its Clerk scope (`orgId ?? userId`); the CLI and daemon write here |
| `FIREBASE_PROJECT_ID` | none | Firestore mirror (optional) | the document mirror's project. All three `FIREBASE_*` vars must be set for the mirror to run |
| `FIREBASE_CLIENT_EMAIL` | none | Firestore mirror (optional) | the service-account email; same env names the landing app uses |
| `FIREBASE_PRIVATE_KEY` | none | Firestore mirror (optional) | the service-account PEM. Literal `\n` escapes (as copied from JSON) are unescaped on load |
| `GITHUB_TOKEN` | none | `ingest` (or `gh auth`) | read GitHub history; falls back to `gh auth token` |
| `LINEAR_API_KEY` | none | Linear ingest | enables the Linear source when set |
| `GRANOLA_API_KEY` | none | Granola ingest | enables `relic ingest --source granola` when set |
| `NOTION_API_KEY` | none | Notion ingest | enables `relic ingest --source notion` when set (an internal integration token) |
| `ANTHROPIC_API_KEY` | none | Phase 4 compiler | skill compilation (not used yet) |
| `REGISTRY_DB_PATH` | `./data/registry.db` | skill commands | SQLite registry location |
| `TARGET_REPO` | none | optional | default `owner/name` for `recall`, `query`, `serve`, and the daemon's fallback scope |
| `FETCH_CONCURRENCY` | `10` | `ingest` | concurrent GitHub requests (rate-limit safe) |
| `RELIC_HTTP_TOKEN` | none | `serve-http` (optional) | when set in the environment, `serve-http` requires `Authorization: Bearer <token>` on its data routes; the `--token` flag overrides it. Leave unset for local dev |
| `RELIC_DAEMON_TOKEN` | none | `daemon` (optional) | same bearer scheme for the daemon routes; `relic install-hooks` bakes it into the hook commands |

Unknown keys in `.env` are ignored (`extra="ignore"`), so a leftover variable
from an earlier version does no harm. The graph-era variables (`FALKORDB_*`,
`OPENAI_API_KEY`, `GEMINI_*`, `GRAPHITI_*`, `BULK_*`, `SEMAPHORE_LIMIT`) are
gone with the graph ([ADR-0007](/adr/0007-engram-store-pivot)); a stale `.env`
still loads clean.

## Secret sanitization

<Warning>
The secret fields (`anthropic_api_key`, `github_token`, `linear_api_key`,
`granola_api_key`, `notion_api_key`) are cleaned after load: a value that is
blank, contains whitespace, or starts with `#` is treated as unset. The reason
is that a `.env` copied from `.env.example` can leave an inline comment as the
value (python-dotenv keeps `KEY=  # note`), and a real API token never contains
whitespace or `#`. So `.env.example` keeps comments on their own lines, and a
half-filled `.env` fails clean rather than sending a garbage credential.
`FIREBASE_PRIVATE_KEY` is the exception: a PEM legitimately contains whitespace,
so it only unescapes `\n` and treats blank as unset.
</Warning>

## The stores

Postgres holds the memory; everything else lives under `./data/` (gitignored)
or, optionally, in Firestore.

<CardGroup cols={2}>
  <Card title="The engram store (memory)" icon="brain" href="/memory-and-recall">
    Postgres, addressed by `DATABASE_URL`. Not a local file: it is a networked
    service (`just up` runs it in Docker). Holds `workspaces`, `people`,
    `memories`, `memory_people`, and `memory_paths`; the schema is applied by
    `ensure_schema()` on first use.
  </Card>
  <Card title="The Firestore mirror (documents)" icon="file-lines" href="/memory-and-recall">
    Optional, configured by the three `FIREBASE_*` vars. One document per memory
    with rendered markdown, for the web workspace. Unconfigured, documents stay
    local-only in `memories.body`.
  </Card>
  <Card title="The registry (skills)" icon="database" href="/skills">
    SQLite at `REGISTRY_DB_PATH`. Created on first write.
  </Card>
  <Card title="The raw store" icon="box-archive" href="/ingestion">
    Plain JSON under `./data/raw/<source>/<id>.json`, written by `ingest`.
  </Card>
  <Card title="The episode spool" icon="layer-group" href="/ingestion">
    Mapped episodes under `./data/spool/<scope>/`, one JSON file per episode.
    Written by capture (`ingest`), read by `relic load`. It decouples capture
    from the store write.
  </Card>
  <Card title="The ingest checkpoint" icon="list-check" href="/ingestion">
    A per-scope ledger at `./data/ingest/<scope>.log`, one landed episode name
    plus its content token per line. Lets a re-run skip what already loaded and
    refresh what changed. `ingest --fresh` clears it.
  </Card>
</CardGroup>

## Logging

Logs are diagnostics and go to stderr; a command's result goes to stdout. The
default level is `INFO` (phase counts, the run summary). `relic --verbose` (or
`-v`, before the command) drops it to `DEBUG`. Logging attaches to the `relic`
logger only, so third-party `INFO` chatter stays suppressed
([`obs.py`](https://github.com/buildrelic/relic-core/blob/main/packages/relic-core/src/relic/obs.py)).

`relic ingest` shows a live progress bar over the load phase on an interactive
terminal. It is suppressed automatically when output is piped/redirected or under
`--verbose` (DEBUG logs would churn it), and can be turned off explicitly with
`relic ingest … --no-progress`; in all those cases you get the `loaded x/y`
heartbeat log lines instead. The bar and the log handler share one stderr console
so log lines render above the bar instead of corrupting it.

## What keys unlock

`relic doctor` reports each key and what it unlocks
([`doctor.py`](https://github.com/buildrelic/relic-core/blob/main/packages/relic-cli/src/relic/doctor.py)):

| Key | Unlocks |
|---|---|
| anthropic | skill compiler |
| github | github ingest |
| linear | linear ingest |
| granola | granola ingest |
| notion | notion ingest |

The core loop (ingest, recall, the daemon) needs no model API key at all: the
store is deterministic end to end.

## Reading doctor

`relic doctor` is a read-only health check. It reports:

- **registry.** Path, whether it exists, and a count of skills by status. If it
  does not exist, it tells you to run `relic register`.
- **engram.** The Postgres DSN (redacted: no password) and whether the host and
  port are reachable (a 0.5s TCP probe), plus whether the Firestore mirror is
  configured or documents stay local-only.
- **keys.** Each key, set or missing, and its purpose.

It opens the registry only when the file already exists and never raises, so a
broken setup still produces a readable report.
