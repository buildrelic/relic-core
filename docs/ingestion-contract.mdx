This page is the handoff from ingestion (Paris, `relic-ingest`) to the engram
(Abhinav, `relic-engram`). It pins what ingestion produces and what the engram
side derives from it. The goal is the best possible compiled skills: ingestion
captures and structures the signal, derive lands it as searchable rows, the
detector mines it, the compiler grounds it.

## The contract is code, not prose

The seam is a typed, versioned model, so the two sides cannot drift:

- **Schema:** [`relic.contracts.episode_body`](https://github.com/buildrelic/relic-core/blob/main/packages/relic-core/src/relic/contracts/episode_body.py)
  (`PrEpisodeBody`, `IssueEpisodeBody`, `DocEpisodeBody`,
  `ConversationEpisodeBody`, `AgentSessionEpisodeBody`, `SCHEMA_VERSION`).
  Ingest builds it; the engram side (`relic.engram.derive`) validates the
  `EpisodeSpec.body` string against the same model.
- **Producer:** [`mappers.py`](https://github.com/buildrelic/relic-core/blob/main/packages/relic-ingest/src/relic/ingest/mappers.py)
  (`pr_to_episode`, `issue_to_episode`, `meeting_to_episode`, `page_to_episode`)
  plus `session_to_episode` for the daemon's capture path.
- **Consumer:** [`derive.py`](https://github.com/buildrelic/relic-core/blob/main/packages/relic-engram/src/relic/engram/derive.py),
  one pure builder per artifact type, checked by
  [`tests/test_derive.py`](https://github.com/buildrelic/relic-core/blob/main/tests/test_derive.py).
- **Executable contract:** [`tests/test_contract_episode.py`](https://github.com/buildrelic/relic-core/blob/main/tests/test_contract_episode.py)
  pins the invariants below and carries `canonical_pr_record()` / `canonical_issue_record()`,
  the reference instances to tune derivation and the detector against.

The full body shape is documented in [Data model](/data-model).

## Source taxonomy (development sources)

There is one body model per development **artifact type**, not per connector:
sources collapse onto the artifact type, source-specific fields stay optional.
Five are populated today (`pull_request`, `issue`, `doc`, `conversation`,
`agent_session`); the rest are defined in
[`episode_body.py`](https://github.com/buildrelic/relic-core/blob/main/packages/relic-core/src/relic/contracts/episode_body.py)
as the full target, with capture landing wave by wave. Each carries a top-level
`url` citation anchor (`pull_request`/`issue` keep theirs nested), so `derive`
resolves the row's `url` column, and with it a source for every fact, with no
per-source change.

| Artifact type | `source_type` | Body model | Sources that map onto it | `source_description` | Grounded in | Status |
|---|---|---|---|---|---|---|
| Pull request | `pull_request` | `PrEpisodeBody` | GitHub PR, GitLab MR, Bitbucket PR | `github pull request` | review-routing fields | **populated** |
| Issue / ticket | `issue` | `IssueEpisodeBody` | GitHub issue, Linear, Jira | `github issue` / `linear issue` | none | **populated** |
| Commit | `commit` | `CommitEpisodeBody` | git / GitHub / GitLab commit | `github commit` | Conventional Commits | defined |
| Release | `release` | `ReleaseEpisodeBody` | GitHub/GitLab release, tag | `github release` | SemVer + Keep a Changelog + DORA | defined |
| CI / CD run | `ci_run` | `CiRunEpisodeBody` | GitHub Actions, GitLab pipeline, deploy | `github ci run` | DORA four keys | defined |
| Incident | `incident` | `IncidentEpisodeBody` | postmortem, PagerDuty, incident.io | `incident` | Google SRE postmortem + DORA MTTR | defined |
| Doc | `doc` | `DocEpisodeBody` | Notion page (wired), README/CONTRIBUTING/ADR/runbook, Confluence | `notion page` | MADR + Diataxis | **populated** (Notion) |
| Discussion | `discussion` | `DiscussionEpisodeBody` | GitHub Discussions, RFC, Q&A | `github discussion` | GitHub Discussions (category/answer) | defined |
| Conversation | `conversation` | `ConversationEpisodeBody` | Granola meeting (wired), Slack thread, Discord | `granola meeting` | decision + action-item capture | **populated** (Granola) |
| AgentSession | `agent_session` | `AgentSessionEpisodeBody` | Claude Code coding session (other coding agents later) | `Claude Code session (relic daemon)` | coding-agent work-session, see [ADR-0001 AgentSession amendment](/adr/0001-engram-graph-ontology) | **populated** (daemon capture) |

The `source_type` discriminator names the **artifact type**, not the connector
(github vs linear is carried by `EpisodeSpec.source_description` and the
identifier/URL). For mutable sources (docs, conversations), the episode name
keys on the stable artifact id (`Notion <page id>`, `Meeting <meeting id>`),
never the mutable content: a re-capture whose content changed supersedes the row
in place through the upsert on `(workspace_id, name)`, so an edited page is one
refreshed memory, not a fork and not a frozen-in-place stale one.

## What ingestion now emits (review-routing first)

Beyond the previous body, the PR episode now carries the review-routing signals:

| Field | Use |
|---|---|
| `requested_reviewers[].kind` (`user`/`team`) | who a PR was *sent to*, person vs team routing |
| `files[].additions` / `.deletions` | per-file churn for area/path routing |
| `pull_request.labels` | area/type taxonomy (`area:auth`, `type:fix`) |
| `pull_request.diff_stats` | PR-level size, a risk-weight input |
| `pull_request.base_ref` / `head_ref` | branch convention / hotfix detection |
| `commits[]` (sha, message, author_login) | active-maintainer + commit-convention signal |
| `linked_issues[]` (`closes`/`resolves`) | the issue↔PR lifecycle edge |
| `pull_request.timestamps` | derived first-review / approval / time-to-merge |
| `context` | a one-line deterministic summary, carried in the body |

Issues now carry the Linear `description` (previously not even queried). `checks`
and the Linear workflow fields (`priority`, `estimate`, `cycle`, `state_history`,
`relations`) are reserved in the contract and default empty: a later wave fills them.

## What derive feeds (the engram write)

[`derive.py`](https://github.com/buildrelic/relic-core/blob/main/packages/relic-engram/src/relic/engram/derive.py)
turns each body into the row the store writes, deterministically. Dispatch keys
on `source_type`; an unknown or malformed body degrades to a raw-text row rather
than failing the episode. Per body type:

| Body | title / url | search_text | people (role) | paths |
|---|---|---|---|---|
| `pull_request` | PR title / PR url | title, description, labels, base/head refs, author, reviews (login, state, comment), requested reviewers, commit messages, file paths (whole and segment-split), linked issues | author (`author`), reviewers (`reviewer`), requested user reviewers (`requested_reviewer`) | `files[].path` |
| `issue` | issue title / issue url | identifier, title, description, state, labels, assignees | assignees (`assignee`) | none |
| `doc` | doc title / doc url | title, body text, author logins | authors (`participant`) | none |
| `conversation` | meeting title / source url | title, summary, transcript, participants, decisions, action items | participants (`participant`) | none |
| `agent_session` | session title / session id | title, summary, transcript, cwd leaf, decisions, touched paths | actor (`author`) | `files_touched[].path` |

Every builder also renders the `markdown` the web workspace displays and lets a
human edit. Labels, areas, and paths stay deterministic text and join rows
(`search_text`, `memory_paths`), never LLM-minted entities: free-text entities
fork, and the detector is deterministic. File-area grouping stays detector-side
from `memory_paths.path` (or CODEOWNERS); temporal ordering stays detector-side
from `reference_time`.

## Invariants (do not break)

- **Citation anchors.** `derive` reads `pull_request.url` / `issue.url` (or the
  top-level `url`) into the row's `url` column, which every recalled fact cites.
  Preserve those keys, or co-change
  [`derive.py`](https://github.com/buildrelic/relic-core/blob/main/packages/relic-engram/src/relic/engram/derive.py).
- **The name is the identity.** `schema_version` and new fields live in the body,
  never in `EpisodeSpec.name`; the checkpoint dedups on `name` and the store
  upserts on `(workspace_id, name)`.
- **Terminal snapshots, refreshed in place.** PRs are still captured only at a
  terminal state, so fields are stable at ingest. When a re-presented body's
  bytes do change, the checkpoint's content token flags it and the upsert
  refreshes the row in place; there is no fork and no removal pass.
- **Budgeted body.** The body is trimmed to a budget (`_fit_budget`), so a
  pathological artifact cannot bloat its row or its search text.

## Measure each wave

End-to-end skill quality is unmeasurable until the detector/compiler land, so
gate on the recall scorecard: `relic eval` scores recall against a gold set
(hit rate, MRR, coverage) with a deterministic URL match, no LLM judge. Run it
before and after a capture or derivation change and diff. `relic query` is the
routing probe (the people connected to work matching an area, ranked by
support), the shape the detector will run. See
[Memory and recall](/memory-and-recall).

## Resolved by the pivot

The open questions this page used to carry were graph-shaped (which edge types
to add, `REQUESTED_REVIEW` vs a discriminator, where `graph_stats.py` lives).
ADR-0007 settled them structurally: reviewer relationships are `memory_people`
roles, touched files are `memory_paths` rows, labels are search text, commits
stay inline body text, and `eval/graph_stats.py` was removed with the graph.
An unknown `schema_version` is best-effort by construction: `derive` degrades a
body it cannot validate instead of failing the episode.
