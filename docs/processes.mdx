Relic is a set of processes over shared stores, not one running service. This doc
catalogs every process: what triggers it, what it reads and writes, what it
depends on, and how long it lives.

Most processes are one-shot CLI commands. Three are long-running servers
(`serve`, `daemon`, `serve-http`). One is a persistent service the platform runs
(Postgres). A few are stubs that land in later phases.

Every command is a subcommand of the `relic` CLI in the `relic-cli` package, the
composition root: it imports each subsystem's public API (`relic.ingest`,
`relic.engram`, `relic.serve`) and wires them together. The subsystems never call
each other directly. See [Architecture](/architecture).

| `relic register` | CLI | one-shot | a JSON file | registry | none |
| `relic list` / `show` | CLI | one-shot | registry | nothing | none |

Every CLI process is import-light: only typer and rich load at startup, and each
command imports its heavy dependencies inside the command body, so `relic --help`
is fast and key-free ([`cli.py`](https://github.com/buildrelic/relic-core/blob/main/packages/relic-cli/src/relic/cli.py)).

## Service processes

### Postgres

The engram store. Relic runs it locally as a Docker container
([`docker-compose.yml`](https://github.com/buildrelic/relic-core/blob/main/docker-compose.yml),
`postgres:16-alpine`).

- **Start.** `just up` runs `docker compose up -d --wait postgres`, blocking
  until the healthcheck passes. `just down` stops it, `just logs` tails it.
- **Port.** `5432`, addressed by `DATABASE_URL` (the default matches compose).
- **Schema.** Owned by relic-core, applied by the idempotent `ensure_schema()`
  on every store open. No migrations to run by hand.
- **Persistence.** A Docker named volume, `postgres-data`. `just reset-db` wipes
  it (every workspace's memories, not one).
- **Required by.** `ingest`, `load`, `recall`, `query`, `eval`, and `serve` when
  recall is enabled. Start it before any of them. The daemon boots without it
  and degrades per-request.

In production this becomes a hosted Postgres instance (e.g. Neon). See
[Roadmap](/roadmap).

### relic serve

The MCP server. It exposes a team's verified skills and its memory to any MCP
client over stdio.

- **Invocation.** `relic serve`. Stays up for the life of the client connection
  (`server.run_stdio_async()`).
- **Exposes.** Each verified skill as a tool (call it for the steps) and as a
  resource at `skill://<id>`; a `search_skills` tool; and, when the store is
  reachable, a `recall_memory` tool.
- **Reads.** The SQLite registry for skills. The engram store for `recall_memory`.
- **Writes.** Nothing.
- **Recall is optional.** The server opens the engram store for recall. If that
  fails (Postgres down), it logs to stderr and serves skills anyway. Diagnostics
  go to stderr because stdout is the MCP transport and any stray bytes corrupt
  the stream ([`cli.py`](https://github.com/buildrelic/relic-core/blob/main/packages/relic-cli/src/relic/cli.py),
  `_serve`).
- **Client config.** Point any MCP client at it over stdio. For Claude Code, add
  it to `.mcp.json`. See [Skills](/skills).

### relic daemon

The closed-loop server. A loopback HTTP surface the Claude Code hooks call on
every turn: inject recalled context onto the prompt, capture the finished
session back into the engram.

- **Invocation.** `relic daemon [--repo owner/name] [--host] [--port] [--token]`.
  Listens on `127.0.0.1:8788`.
- **Routes.** `GET /v1/daemon/status` and `activity`; `POST /v1/daemon/inject`,
  `recall`, and `capture`. See [CLI reference](/cli-reference#relic-daemon).
- **Reads and writes.** The engram store, scoped per session: each call resolves
  the repo from the session's working directory (its git origin), falling back
  to `--repo` or `TARGET_REPO`.
- **Degrades, never breaks a turn.** The store is built lazily, so the daemon
  boots with Postgres down and errors per-request instead.
- **Install.** `relic install-hooks` merges the two Claude Code hooks
  (`UserPromptSubmit` to inject, `SessionEnd` to capture) into settings.json.

### relic serve-http

The web app's control plane: connector status, ingest run history, and the
ingest trigger, on `127.0.0.1:8787`.

- **Invocation.** `relic serve-http [--host] [--port] [--token]`.
- **Reads.** The ingest checkpoints and the run ledger
  (`data/ingest/runs.jsonl`) on disk. The status routes need no store.
- **Writes.** Nothing directly; `POST /v1/ingest` spawns a `relic ingest`
  subprocess (which needs Postgres and the source keys), forwarding an optional
  per-user token and `workspace`. See [Web app HTTP contract](/web-contract).

## Capture and memory processes

### relic ingest

The capture pipeline. Pulls a source's history into the engram store.

- **Invocation.** `relic ingest --repo owner/name [--source github|granola|notion] [--limit N] [--months M] [--fresh] [--no-progress] [--no-load]`.
- **Reads.** GitHub GraphQL (merged PRs with files and reviews, batched per page) and
  GitHub REST (non-PR issues); both windowed to the last `--months`. Linear GraphQL when
  `LINEAR_API_KEY` is set. `--source granola` and `--source notion` pull meetings
  and pages instead. Plus the per-scope checkpoint ledger.
- **Writes.** The engram store (one memory row per artifact, landed under the
  workspace and the scope slug); the raw store at `./data/raw/<source>/<id>.json`;
  the episode spool at `./data/spool/<scope>/`; the checkpoint at
  `./data/ingest/<scope>.log`. The Firestore document mirror when configured,
  best-effort.
- **Depends on.** The source credential (a GitHub token from `GITHUB_TOKEN` or
  `gh auth token`, else the granola or notion key) and Postgres. No model API key.
- **Two halves.** A deterministic capture (fetch, map, raw store, spool), then
  the engram write. `--no-load` runs only the first half and stops, leaving the
  episodes spooled for a later `relic load`.
- **Flow.** Probe Postgres, fetch the window (PRs in one batched GraphQL query
  per page), dump raw, map to typed episodes, then land each episode: derive the
  row fields and upsert on `(workspace_id, name)`. Sequential, milliseconds per
  episode; there is no bulk path because there is no extraction I/O to overlap.
- **Resumable.** The checkpoint records each landed episode with its content
  token, so a re-run skips unchanged episodes and refreshes changed ones in
  place. `--fresh` clears it and re-presents everything (the upsert makes that
  safe).
- **Observable.** Logs the fetch counts and timing, per-episode failures, and a
  final loaded/refreshed/skipped/failed summary, all to stderr.
  `relic --verbose ingest` adds debug detail.
- **`--limit`.** Caps items pulled, most recent first, to bound API cost on a
  large repo.

Full detail in [Ingestion](/ingestion).

### relic load

The engram write, run on demand: the second half of ingest.

- **Invocation.** `relic load --repo owner/name [--source github|granola|notion] [--limit N] [--fresh] [--no-progress]`.
- **Reads.** The episode spool at `./data/spool/<scope>/`, written by a prior
  `relic ingest` (or `relic ingest --no-load`); the per-scope checkpoint ledger.
- **Writes.** The engram store (one memory row per artifact, upserted in place);
  the checkpoint at `./data/ingest/<scope>.log`; the Firestore mirror when
  configured.
- **Depends on.** Postgres. No source credential: it reads the spool, not the
  network.
- **Resumable.** Shares the checkpoint with `ingest`, so it skips unchanged
  episodes and a re-run only lands what is new or changed. An empty spool is a
  no-op.
- **`--limit`.** Lands at most N not-yet-loaded episodes for case-by-case
  loading. Re-run to drain the rest. `--fresh` ignores the checkpoint and
  re-presents every spooled episode.

Full detail in [Ingestion](/ingestion).

### relic recall

General memory recall. Returns facts with their sources.

- **Invocation.** `relic recall "question" [--repo owner/name] [--num-results N]`.
- **Reads.** The engram store, narrowed to a repo's scope (defaults to
  `TARGET_REPO`; workspace-wide without one).
- **Writes.** Nothing. Prints a cited, human-readable block.
- **Depends on.** Postgres. The search is full-text (`websearch_to_tsquery` with
  an any-term fallback); no model API call.
- **Never raises.** If search fails, it returns an empty answer rather than an
  error ([`recall.py`](https://github.com/buildrelic/relic-core/blob/main/packages/relic-engram/src/relic/engram/recall.py)).

### relic query

A narrower, people-focused query. Finds people connected to work matching the
text: one SQL query over the `memory_people` roles, the `memory_paths` table,
and full-text search.

- **Invocation.** `relic query "text" [--repo owner/name]`.
- **Reads.** The engram store, narrowed to a repo's scope.
- **Writes.** Nothing. Prints each person, their relation, the fact, profile URL,
  and source memories, de-duplicated by name.
- **Depends on.** Postgres.

### relic eval

The recall scorecard. Measures whether recall cites the PR or issue that actually
holds each answer.

- **Invocation.** `relic eval [--path eval/github_recall.json] [--num-results N]
  [--json out.json]`.
- **Reads.** A gold set JSON (questions plus the PR or issue numbers that answer
  them); the engram store.
- **Writes.** Nothing by default. Prints three metrics (hit rate, MRR, coverage)
  plus a per-case pass or miss line; with `--json`, also writes the run as
  machine-readable JSON for tracking metrics across runs.
- **Depends on.** Postgres.
- **No LLM judge.** Scoring is a deterministic URL match, so the ruler itself
  costs nothing beyond the recall calls it measures
  ([`scorecard.py`](https://github.com/buildrelic/relic-core/blob/main/packages/relic-engram/src/relic/scorecard.py)).

## Skill and registry processes

These read and write the SQLite registry. None touches the engram store or the
network.

### relic register

Load a hand-authored `SkillIR` JSON file into the registry. The manual authoring
path until the Phase 4 compiler produces skills.

- **Invocation.** `relic register path/to/skill.json`.
- **Reads.** The JSON file (validated against `SkillIR`; invalid input exits 1).
- **Writes.** The registry. Upsert by `skill_id`, preserving `created_at`.

### relic list, relic show

Inspect the registry.

- **`relic list [--status draft|verified|deprecated]`.** Prints a table of skills.
- **`relic show <skill_id> [--json]`.** Prints the rendered `SKILL.md`, or the raw
  `SkillIR` JSON with `--json`.

### relic verify, relic deprecate

Move a skill through its lifecycle. Each mutation rewrites the stored document so
a reloaded `SkillIR` always matches its row.

- **`relic verify <skill_id>`.** Promotes draft to verified and stamps
  `last_verified_at`. Refuses to verify a deprecated skill.
- **`relic deprecate <skill_id>`.** Marks a skill deprecated so it stops being
  emitted or served.

### relic emit

Write verified skills to a target repo's `.claude/skills/`, and reconcile.

- **Invocation.** `relic emit --repo /path/to/target-repo`.
- **Reads.** The registry.
- **Writes.** One `.claude/skills/<id>/SKILL.md` per verified skill, plus a
  `README.md` catalog index. Removes the directories of registry skills that are
  no longer verified.
- **Reconciles, does not clobber.** It only touches skill directories whose id
  matches a skill in the registry, so hand-authored skills under `.claude/skills/`
  are left alone ([`emit_files.py`](https://github.com/buildrelic/relic-core/blob/main/packages/relic-serve/src/relic/serve/emit_files.py)).

### relic catalog

Print the browsable markdown index of verified skills to stdout (the same index
`emit` writes to the target repo).

## Diagnostics

### relic doctor

A read-only health check. Reports where the registry lives and how many skills it
holds by status, whether the engram store is reachable and its Firestore mirror
configured, and which API keys are configured. It creates nothing and never
raises: a broken setup still produces a readable report
([`doctor.py`](https://github.com/buildrelic/relic-core/blob/main/packages/relic-cli/src/relic/doctor.py)).

- **Invocation.** `relic doctor`.
- **Reads.** The registry (only if the file exists), settings, and a TCP probe of
  the Postgres host and port (the DSN is printed with the password redacted).
- **Writes.** Nothing.

## External processes the platform calls

These run outside Relic, invoked per command as HTTP calls.

- **GitHub.** Source for `ingest`, via `githubkit`: merged and closed PRs come from the GraphQL API in one batched query per page, non-PR issues from the REST list endpoint.
- **Linear GraphQL.** Optional source for `ingest`, via `gql`, guarded behind
  `LINEAR_API_KEY`.
- **Granola.** Optional source (`ingest --source granola`), guarded behind
  `GRANOLA_API_KEY`.
- **Notion.** Optional source (`ingest --source notion`), guarded behind
  `NOTION_API_KEY`.
- **Firestore.** The optional document mirror, via `firebase-admin`, guarded
  behind the `FIREBASE_*` service account. Best-effort: an outage never fails an
  ingest.
- **Anthropic.** The Phase 4 skill compiler. Not called yet. No model API is
  called at ingest or recall.

## Pending processes

These are stubs today. See [Roadmap](/roadmap).

- **`relic resolve` (Phase 3).** Unify a person across GitHub and Linear into one
  `Person` row. Prints "not implemented yet" and exits 1.
- **`relic compile` (Phase 4).** Detect a recurring procedure and compile it into
  a grounded `SkillIR`. Invoked as `relic compile --skill <archetype>`. Prints
  "not implemented yet" and exits 1. The detector
  ([`detect.py`](https://github.com/buildrelic/relic-core/blob/main/packages/relic-engram/src/relic/compile/detect.py)) and compiler
  ([`compiler.py`](https://github.com/buildrelic/relic-core/blob/main/packages/relic-engram/src/relic/compile/compiler.py)) are docstring-only stubs;
  the renderer ([`render.py`](https://github.com/buildrelic/relic-core/blob/main/packages/relic-serve/src/relic/serve/render.py)) is already wired.
- **`pipeline/run.py` (Phases 4 to 8).** The full-run orchestrator (ingest,
  resolve, detect, compile), the eventual Cloud Run Job entry point. Raises
  `NotImplementedError`.
